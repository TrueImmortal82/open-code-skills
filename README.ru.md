Устанавливаемый плагин для [OpenCode](https://opencode.ai), который приносит
набор агентских скилов. Поставил один раз — они есть в каждой сессии.

| | |
| --- | --- |
| ID плагина | `open-code-skills` |
| Требуется | OpenCode `>= 1.18.0` |
| Рантайм | Bun — Node.js не нужен |
| Лицензия | MIT |

## Как это работает

Плагин экспортирует один хук `config`. При старте он добавляет свою папку
`skills/` в `skills.paths` живой конфигурации, и штатный механизм обнаружения
OpenCode подхватывает скилы. Ничего не копируется в глобальные каталоги.

## Скилы

| Скил | Для чего |
| --- | --- |
| `powershell-windows` | Правила PowerShell 5.1: цепочки команд, `$?` против `$LASTEXITCODE`, кавычки, не-UTF-8 кодировка консоли, внешние exe |
| `opencode-config-authoring` | Создание и починка `opencode.json` / `opencode.jsonc`, плюс валидатор JSONC и схемы |
| `skill-authoring` | Как написать скил, который действительно срабатывает: каркас и валидатор |
| `self-improvement` | Превращение замечания в постоянный артефакт, а не в забытое намерение |
| `code-discipline` | Стандарты кода и жёсткие бюджеты размера: файл 300/500 строк, функция 30/50, ни одной новой зависимости без спроса |
| `assistant-runtime-architecture` | Долгоживущий ассистент-рантайм: supervisor и дочерний процесс, надёжная доставка, контракты вывода |
| `opencode-tool-output` | Разбор JSON из `opencode debug` вместо regex, плюс ловушки запуска на Windows: GUI-бинарник и шим `opencode.cmd` |
| `test-first-fix` | Сделать отказ наблюдаемым до правки кода, чтобы исправление было утверждением, которому машина может возразить |
| `git-safety` | Проверить состояние дерева git до разрушающей команды и вернуть уже потерянную работу |
| `github-repo-ops` | Работать с `gh` в рамках реально доступных scope и восстанавливаться после 403 «Resource not accessible» |
| `release-checklist` | Те проверки перед релизом, которые пропускают под дедлайном, с падением сразу по всем сразу |
| `troubleshooting-tree` | Делить пространство неизвестной причины пополам вместо угадывания исправлений |
| `long-task-continuity` | Постоянная контрольная точка, чтобы длинная задача пережила сброс контекста или падение |
| `api-doc-recall` | Сверять API с установленным исходником, а не с памятью о документации |
| `research-synthesis` | Сводить несколько источников в один ответ и явно отмечать, что подтверждено, что предположено, что неизвестно |
| `task-closure` | Решать, что задача закончена, вместо бесконечных улучшений: условия остановки, тест на готовность и список того, что уходит в следующую задачу |

Каждый скил — обычный каталог с `SKILL.md` и YAML-фронтматтером по
[спецификации Agent Skills](https://agentskills.io/specification). Их можно
скопировать из репозитория и использовать вообще без плагина.

## Установка

Добавь в `~/.config/opencode/opencode.jsonc` (глобально) или
`.opencode/opencode.json` (для проекта):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["github:TrueImmortal82/open-code-skills"]
}
```

После этого перезапусти OpenCode — конфигурация не перезагружается на лету.

### Если спецификация с GitHub не сработала

Прямая установка зависит от того, передаёт ли твоя версия OpenCode спецификацию
установщику пакетов. Если нет — склонируй репозиторий и укажи каталог, это
поддерживают все версии:

```bash
git clone https://github.com/TrueImmortal82/open-code-skills.git
```

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["C:/path/to/open-code-skills"]
}
```

Пиши прямые слэши; обратные экранируй, если записываешь путь Windows буквально.

### Проверка

```bash
opencode debug skill
```

Каждый скил должен появиться, а `location` — указывать внутрь установленной
копии репозитория.

## Часть скилов вместо всех

Скилы регистрируются по каталогам, поэтому удаление папки скила из своей копии
убирает его из установки. Чтобы сохранить локальную правку одного скила и при
этом обновлять остальные, скопируй его в `~/.config/opencode/skills/` — местные
скилы участвуют в том же проходе обнаружения.

## Разработка

```bash
git clone https://github.com/TrueImmortal82/open-code-skills.git
cd open-code-skills
npm run validate
```

`npm run validate` прогоняет встроенный валидатор по каждому скилу и падает на
ошибках фронтматтера, битых ссылках и слишком длинных телах.

```bash
node skills/skill-authoring/scripts/new-skill.mjs
node skills/skill-authoring/scripts/validate-skill.mjs skills/<your-skill>
node skills/code-discipline/scripts/check-size.mjs .   # бюджет файлов и зависимостей
```

## Как участвовать

- В модуле плагина должен быть **ровно один** экспорт — объект по умолчанию.
  Устаревший загрузчик OpenCode считает каждый именованный экспорт отдельным
  плагином и падает на всём, что не функция.
- Хук `config` получает живой объект конфигурации; возврат игнорируется, ошибки
  проглатываются. Мутируй на месте и никогда не бросай исключения.
- Не вкладывай `SKILL.md` внутрь каталога другого скила: пути сканируются
  рекурсивным глобом `**/SKILL.md`, и вложенный файл зарегистрируется как
  второй, нежелательный скил.
- Не вшивай машинно-специфичные значения — абсолютные пути, кодовые страницы
  консоли, домашние каталоги. Определяй окружение.
- `SKILL.md` описывает поведение, а не раскладку файлов: говори, что делает
  скрипт, а не в каком модуле какая проверка.
- `self-improvement/queue.md` — живой журнал, свои записи добавляй свободно.
